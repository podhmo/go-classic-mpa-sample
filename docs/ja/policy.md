# 作業ポリシー（Policy）

このプロジェクトでユーザーから指示・助言された作業方針を記録する。以後の作業でも原則として従う。

## タスク分解・実行

- **大きなタスクは `TODO.md` に分解してから実装する**。仕様書（例: `docs/ja/prompts.md`）をそのまま実行せず、チェックリスト化して進捗を追えるようにする。
- **サブエージェントは最大2個まで**並行利用してよい。各エージェントには worktree（`git worktree`）と専用ブランチを与え、触るファイル範囲を明確に制限する。
- **サブエージェントには自由にコミットさせてよい**。worktree も自由に作らせてよい。
- **マージは親エージェント（このセッションのエージェント）が行う**。エージェントの成果物は main に取り込んで統合・検証する。
- **マージ後の作業には新しいサブエージェントを使う**。既存エージェントのコンテキストを引き継ぐ（resume）より、新規起動したほうがコンテキスト汚染がなく確実。

## 記録・ドキュメント

- **落とし穴・ハマったところは `docs/ja/pithole.md` に記録する**。後で同じ罠にかからないようにするため。
- **決めたこと・設計判断は `docs/ja/decisions.md` に記録する**。
- **見つけたバグは `docs/ja/bugs.md` に記録する**。すべて修正するとは限らないが、記録して忘れないようにする。重要度・状態（未修正/修正済み/対応しない）を併記する。

## 品質・検証

- **バグ取りに手間取るならテストを書かせる**。網羅的でなくてよい — 怪しい箇所を固定するテストを書くほうが、手動検証を続けるより近道になりうる。
- 検証は実際に動かして確認する（`go test ./...`、実サーバー起動 + HTTP リクエスト）。
