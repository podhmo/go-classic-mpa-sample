# UI ルール（ui-rules）

本アプリの UI 規約を 1 箇所に集約した文書。外部のプリミティブ・デザイン
システム チェックリスト（全 41 項目）との突き合わせ監査（2026-11-16
実施）を元に、現行実装で「正」とする規約・採用した代案・変更が必要な
項目・対象外（N/A）を分けて記載する。

個別の設計経緯・根拠は `docs/ja/decisions.md` を参照。ここには結論だけを書く。

## 凡例

- **正** — 現行実装がそのまま規約。新規 UI もこれに従う。
- **正（代案）** — チェックリストの指定形とは異なるが、独自のやり方として採用したもの。
- 代案・独自判断の項目には「元の規定:」として、チェックリストが求めていた形を付記する。
- **変更予定** — 違反・不統一として認識しているもの。対応タスクは `TODO.md` にある。
- **N/A（対象外）** — 該当する UI・機能が存在しない項目。将来機能を足すときの参考として残す。

## 1. ボタンとアクション配置

- [正] **確定系は右、取り消し系は左、右寄せ配置**。`.form-actions` 自体が
  `justify-content: flex-end` を持ち、作成/編集フォーム・GET 削除確認
  ページ・`<dialog>`・返信フォームのすべてで「Cancel（`<a>`/`<button>`）
  → 確定（`<button type="submit">`）」の順に統一済み（2026-11-16）。
- [正] **1 画面 1 プライマリ**（ページ内アクションに限る）。
- [正] **グローバルヘッダの "New issue" / "New discussion" は枠線 `.btn`**。
  Primary はページ内アクション 1 つのみ（2026-11-16 枠線化）。
- [正] **破壊的アクションは `btn-danger`（枠線型・hover で塗り）で抑制し、
  必ず確認を挟む**（モーダル `<dialog>` or GET 確認ページ）。
- [正] **削除モーダルは Cancel に `autofocus`**。Esc・Cancel・背景クリック
  （`closedby="any"`）で閉じる。
- [正] **ボタンラベルは具体動詞**（"Delete issue" "Close issue" "Start thread"）。
  "OK" "はい" 等の抽象語は使わない。
- [正（代案）] **インライン編集は持たず、専用 `/edit` ページ**へのリンクで代替。（元の規定: 1-7 通常時はテキスト右上に「編集 / `...`」、編集モード時は入力枠右下に「キャンセル（左）/ 更新（右）」を置くインライン編集）

## 2. ダイアログ・通知・アラート

- [正] **モーダルはユーザー判断が必須のときのみ**（現状は削除確認のみ）。
  Cancel ボタン・Esc・背景クリックで閉じられる。
- [正] **トーストは投稿成功の確認のみ**（`static/toast.js`）。8 秒で自動消去 +
  Close ボタン。フォーカス中は消えない。エラーには使わない。
- [正] **エラーや要対処の情報は常駐するインライン表示**（`role="alert"` /
  `aria-invalid` + `.field-error`）。

## 3. フォーム・入力

- [正] **ラベルは入力欄の直上**。プレースホルダーをラベル代わりにしない。
- [正] **必須は `*` + "Fields marked * are required." の表記で統一**。
- [正] **エラーは `:user-invalid`（blur 相当）または送信時**に入力欄の直下へ
  赤文言で出す。タイピング中は出さない。
- [正] **Ctrl/Cmd+Enter で送信**（`enter-submit.js`）。`aria-keyshortcuts` と
  `.field-hint` の文言で示唆。
- [正] **二重送信防止**: data-partial 経路は busy フラグ + submit 非活性 +
  `<progress>`。失敗時は入力を消さずインラインエラー（サーバ側もドラフトを
  再描画して保持）。
- [正] **入力中の離脱ガード** — `static/leave-guard.js` が textarea/テキスト
  入力/checkbox・radio（ラベル変更）を持つフォームの未送信変更を検出し
  `beforeunload` で確認する（部分投稿成功＝`reset` イベントで解除。
  auth 系の短いフォームは対象外）。作成/編集フォームと詳細ページに
  読み込む（2026-11-16）。

## 4. 一覧（リスト画面）

- [正（代案）] **行構成は「タイトル行 + メタ行」の 2 段**で統一（decisions.md のコンテナクエリ設計参照）。左端ステータスアイコン・担当者アバター・コメント数は持たない（メタ行のバッジが状態表示を兼ねる）。（元の規定: 4-1 「最左ステータスアイコン → 中央タイトル+ラベル/#ID/日時/著者 → 最右アバター・コメント数」の横並び）
- [正] **詳細へのリンクはタイトルのみ**。行全体はクリック不可。ラベルは
  フィルタ適用の独立リンク。
- [正] **ソート・フィルタはリスト直上**（`.filter-bar`）。適用中は Clear
  リンクを常時表示。

## 5. 詳細（スレッド画面）

- [正（代案）] **単一カラム**。サイドバーに載せるべきメタ情報（担当者等）が機能上存在しないため、ラベル等はタイトル下にインライン表示。（元の規定: 5-1 PC 時は左メイン 70〜75% + 右サイドバー 25〜30% の 2 カラム）
- [正] **本文・コメントはカード**で囲み、左上に「名前・日時・copy link」。
- [正] **ネスト返信は親カード内・左縦線インデント・最大 1 段**
  （store 層でも 2 段目の返信を拒否）。
- [正] **時系列は上→下（古い順）**、新規入力欄は一番下。

## 6. コメント追加 UI

- [正] **トップレベル入力欄は画面最下部に常時展開**、キャンセルボタンなし。
- [正] **コメント欄が空のとき送信ボタンを Disabled に**
  （`static/comment-submit-disabled.js`。トップレベル・返信両方。
  空投稿は 422 しか返せないため、入力があるまでボタンを無効化する
  GitHub 式の方針として採用 — バリデーション表示を妨げる disable とは
  別扱い。2026-11-16）。
- [正（代案）] **返信欄は `<details>` で畳んだ擬似入力バー**（summary 「Add a comment」）。子 0 件 / 1 件以上で同一の見た目（「返信」ボタンのみの形は取らない）。（元の規定: 6-2 子 0 件はフッターに「返信」ボタンのみ / 6-3 子 1 件以上は子一覧の最下部に 1 行の擬似入力欄）
- [正] **展開時は JS で autofocus、`field-sizing: content` で自動伸縮**、
  右下に「Cancel（左）/ Comment（右）」。
- [正] **複数返信欄の排他制御は設けない**。同時に複数開いたままでよい（2026-11-16 決定）。（元の規定: 6-5 空の返信欄は別の返信欄を開いた時に自動で閉じ、入力ありは保持）
- [正（代案）] **返信キャンセルは入力有無を問わず即座に畳む**。破棄確認は出さないが、畳んでも textarea の内容は保持される（再展開で戻る）ため実質データを失わない。（元の規定: 6-6 空なら即畳み、入力ありなら破棄確認を出す）
- [正] **部分投稿の成功後は `<details>` を畳んで元の状態に戻す**
  （partial-submit.js の append パスで `details.open=false`、フォーカスは
  折り畳みバーの summary へ戻す。2026-11-16）。

## 7. メニュー（`...`）と破壊的操作

- [正] **`...` メニューは持たない**。copy link はインラインボタン。
- [正（代案）] アクション行で Edit と Delete は隣接するが、削除は必ず確認モーダル / 確認ページ経由のため誤操作防止は確認側で担保する。（元の規定: 7-2 編集と削除は隣接させない）

## 8. 画面状態・メタデータ

- [正] **Empty**（0件案内+次アクション）と **Error**（error.html + インライン
  エラー）は実装済。Loading は MPA の全画面遷移ではブラウザに委譲、非同期
  投稿は `<progress>` + `aria-busy`。
- [正（代案）] **ステータスバッジは「色+アイコン（::before）+テキスト」の3点セットで、タイトル行の左横**（直下ではなく同段）。（元の規定: 8-2 タイトルのすぐ下・左寄せ）
- [正] **日時は絶対時刻（`fmtTime`）のみ**。相対時刻・ホバーツールチップは採用しない（2026-11-16 決定）。（元の規定: 8-3 相対時間を基本としホバーで絶対時刻ツールチップ）
- [正] **アバター機能は持たず、ユーザー名テキストのみ**を一貫して表示。

## 9. 視覚的階層・スペーシング・表記

- [正] **余白は偶数 px 基準 + 近接の原則**（関連要素同士の余白 < 別グループとの余白）。4 の倍数グリッドは採用しない（2026-11-16 決定）。（元の規定: 9-1 余白・サイズは 4 の倍数のグリッド）
- [正] **色は semantic token**（`--accent` / `--danger` / `--warn` /
  `--open` / `--closed` / `--text` / `--text-muted`、light/dark 両対応）。
- [正] **タッチ端末は `@media (pointer: coarse)` でボタン・入力を 44px
  以上**に引き上げ。
- [正] **英文 UI**。ボタンは動詞、見出し・ラベルは名詞形で統一。
- [正] **リンクは本文テキストと見分けがつく表現にする** — `--accent` 色、
  ボタン/バッジ/タブ等の affordance、あるいは現在地の下線など、「押せる
  もの」と分かる外観であること。古典的 web リンク（青・紫・常時下線）の
  強制はしない（2026-11-16 決定）。現行の `--accent` 色リンク、
  `.btn` 化した `<a>`、badge/tab リンクはこれで許容。
- [正] **`.comment-permalink` は常時下線つき**（muted 色のまま
  `text-decoration-color: var(--text-muted)` で下線表示、hover で accent に。
  2026-11-16）。

## 10. アクセシビリティ・キーボード操作

- [正] **リンクとボタンの使い分け**: 画面遷移は `<a>`、状態変更は
  `<form>` + `<button>`（Cancel が `<a>`、送信が `<button>` の構造を
  全フォームで維持する）。
- [正] **フォーカスリング**: `:focus-visible` で全対話要素に 2px
  アウトライン。スキップリンクを `<body>` 先頭に置く。
- [正] **アイコン・装飾は alt 空 or `aria-hidden`** でアクセシビリティ
  ツリーから外す。繰り返し出るボタンの accessible name は対象 ID 込みで
  一意化する（"Post comment on thread N" パターン。可視ラベルはその
  部分文字列 = WCAG 2.5.3）。
- [正] **現在地表示は色だけに頼らない**: `aria-current="page"` +
  underline・太字の複合（サイトナビ・ステータスタブ・パンくずで共通）。

## 11. 色・テーマ・コントラスト

- [正] **ライト/ダーク両対応**: `light-dark()` + `prefers-color-scheme`
  メディアクエリのフォールバックの 2 系統で定義する。単一スキームの
  ハードコード色は使わない。
- [正] **塗り要素の文字コントラストは 4.5:1 以上を計算で担保**
  （`--accent-emphasis` / `--danger-emphasis` / `--on-emphasis` 系を使う。
  リンク用 `--accent` に直接白文字を載せない）。
- [正] **状態色は形も変える**（Open=中抜きリング、Closed=塗り円の
  `::before`）。色のみに依存した区別をしない。

## 12. タイポグラフィ・モーション

- [正] **フォントは rem 基準**（OS の text-scale・ブラウザ設定に従う。
  px 固定しない。iOS Safari のフォーカスズーム対策として入力は
  `font-size: max(1rem, 1em)`）。
- [正] **アニメーションは `prefers-reduced-motion` で無効化できる**。
  view transition・トランジション系は必ず reduce 系メディアクエリの
  フォールバックを持つ。
- [正] **長文の扱い**: `overflow-wrap: anywhere`、一覧タイトルは 2 行
  クランプ、ラベルバッジは ellipsis + hover/focus 展開。

## 13. 操作フィードバック・その他

- [正] **破壊的でない状態変更は `btn-quiet`**（Mark as answer 等）—
  Primary でも Danger でもない第三の階層。
- [正] **コピー等の小さなフィードバックは `role="status"` のインライン
  表示 + 数秒で消去**（toast までは使わない）。
- [正] **状態変更は POST → 303 → GET（PRG）**。`data-partial` 部分更新の
  アナウンスは toast / live region の 1 系統に統一（複数 region で競合
  させない）。
- [正] **ページネーションは Previous/Next + "Page X of Y"**、端では
  `btn-disabled` の非リンク表記。
- [正] **エラーページはコード表示 + 戻り先リンク 1 本**（error.html）。

## 14. モバイル・タッチ

- [正] **タップターゲットは `@media (pointer: coarse)` で 44px 以上**
  （セクション 9 と同規定。checkbox/radio は除外するが `<label>` 行全体を
  クリック可能にしてカバーする）。
- [正] **hover 前提の UI を作らない**: hover で初めて現れる操作は
  `@media (hover: hover)` でゲートし、タッチ環境では常時表示にする
  （copy-btn のパターン）。
- [正] **狭幅はコンテナクエリ / `auto-fit` で自然に積む**（filter-bar・
  issue-row）。ビューポート基準の 40em ブレークポイントは page-head と
  issue-actions の縦積み用のみ。
- [正] **safe-area-inset 考慮済み**: 固定要素（toast・back-to-top）の
  オフセットに `env(safe-area-inset-*)` を加算。viewport meta に
  `viewport-fit=cover` を付けて env() が値を持つようにした（2026-11-16）。
- [正] **sticky hover 対策統一済み**: 装飾的な `:hover` はすべて
  `@media (hover: hover)` でガード。`:is(:hover, :focus-visible)` 複合は
  focus 側を無条件・hover 側をガードに分離（2026-11-16）。
- [正] **狭画面での固定要素配置**: back-to-top は `max-width: 40em` で
  左下に移動（右寄せの送信ボタンと干渉しない）、`.main-content` の
  `padding-block-end` を拡大して最下部のフォーム操作が固定要素帯より
  上までスクロールできるようにした（toast は一時表示＋Close 付き）。

## 15. ルールの検証方法

- **[正] 静的な見た目のルールは自作 storybook で確認する。** `make storybook`
  （`:6006`）が `internal/web/story_pages.go` のストーリーを描画する。
  一覧・詳細・フォーム・削除確認・エラーページに加え、Empty / ページング /
  バリデーションエラー / 部分更新フラグメント等の状態ストーリーが既にある。
- **[正] 新しい UI 状態を実装したら対応するストーリーを追加する。**
  ルールが「見た目で守れているか」を追えるようにするのが目的。
  （例: 狭画面で固定要素が送信ボタンを覆わないことの目視確認は
  storybook のビューポートを変えて行う）
- **[正] JS が絡む挙動は storybook ではなく実アプリで検証する。**
  storybook はテンプレートの静的描画のみ。disabled 制御・`<details>` の
  畳み・beforeunload・toast の動作は `verify-ui` スキル（実サーバ +
  playwright-cli）で確認する。手順は `docs/ja/for-ui-designer.md` 参照。

## 変更予定のまとめ

監査時点の「変更予定」はすべて実装済み（2026-11-16）。当時のタスク一覧と
対応内容:

1. **ボタン配置の統一** — 作成/編集フォーム・削除確認ページを「左:キャンセル
   / 右:確定・右寄せ」に揃えた。`.form-actions` 自体が `flex-end` を持ち
   `.comment-form`/`.confirm-dialog` の個別例外は撤去（1-1）
2. **ヘッダ New ボタンの枠線化** — `btn-primary` を外し、ページ内 Primary を
   1つにした（1-2）
3. **コメント欄が空のとき送信 Disabled** — `comment-submit-disabled.js`
   （6-1）
4. **返信の部分投稿後に `<details>` を畳む** — partial-submit.js（6-6）
5. **入力中の離脱ガード** — `leave-guard.js`（3-7）
6. **モバイル対応の残件** — `env(safe-area-inset-*)` 加味、`viewport-fit=cover`
   付与、装飾 `:hover` の `@media (hover: hover)` ガード統一、狭画面で
   back-to-top を左下へ移動＋`.main-content` 下端余白の確保（セクション 14）
7. **コメント permalink の判別可能化** — `.comment-permalink` に常時下線
   （セクション 9）
